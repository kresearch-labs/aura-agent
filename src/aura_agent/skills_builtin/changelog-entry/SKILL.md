1. Read the project's CHANGELOG format and the commits since the last entry (`git log`).
2. Group by Added / Changed / Fixed / Removed; one line per user-visible change, in plain words.
3. Leave out internal refactors unless they change behaviour.
4. Name breaking changes clearly at the top.
